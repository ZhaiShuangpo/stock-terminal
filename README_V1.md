# 📈 大A盯盘终端 (Stock Terminal) V1.0 发布说明与技术规格文档

## 1. 项目概述
**大A盯盘终端 V1.0** 是一款专为 A 股投资者设计的现代化、高信息密度 Web 盯盘工具。系统采用“后端行情引擎 + 前端极客交互”的架构，旨在解决传统行情软件信息零散、缺乏即时 AI 逻辑归因以及 Web 端交互卡顿的痛点。

---

## 2. 核心功能特性

### 2.1 全景实时监控 (Market Dashboard)
- **毫秒级推送**：基于 WebSocket 实现行情数据流式推送，界面无刷新平滑更新。
- **高密度列表**：支持自选股自定义拖拽排序（Dnd-kit 驱动），严格遵循 A 股红绿视觉习惯。
- **多维指标**：涵盖现价、涨跌幅、成交量、成交额及 Sparkline 迷你分时趋势图。

### 2.2 极客交互与隐私保护
- **Boss Mode (老板键)**：按 `Esc` 键一键切换至“系统监控”伪装模式。界面转为黑白灰调，隐藏红绿色彩，并将股票名称伪装成系统进程 ID（如 `SVC-0519`），适配办公场景。
- **本地化存储**：自选股分组、API Key 等敏感配置完全存储在浏览器 `localStorage` 中，不经过中心化服务器，保障隐私安全。

### 2.3 AI 证据辅助
- **个股异动分析**：结合联网检索与本地行情快照，区分已确认事实、技术推断和未验证催化，并展示来源与证据置信度。
- **资讯/公告摘要**：优先核验交易所、巨潮资讯和公司公告，分别输出事实方向、短期影响、计价风险与引用来源。
- **智能复盘**：聚焦主要指数、市场宽度和板块轮动，不逐一分析所有股票；输出次日板块启动条件与大盘调整情景。

### 2.4 长线研究与策略验证
- **公司研究**：记录核心逻辑、催化剂、风险、关键指标、持有期限和逻辑失效条件。
- **持续复核**：研究卡片支持编辑与人工复核历史；联网逻辑体检逐项核验 KPI 和证伪条件，并将证据回写研究记录。
- **AI分析同步边界**：个股“AI异动分析”不会自动改写长期核心逻辑。用户可点击“同步到公司研究”：已有卡片时追加为复核证据，没有卡片时创建低置信度的“观察”草稿，并要求人工补齐KPI和证伪条件。
- **组合风险**：依据未平仓模拟记录计算仓位、市值、集中度、行业暴露和基准表现；缺失行业统一显示“未分类”。
- **策略实验室**：对模拟信号做前向验证，记录入场快照、信号来源、策略版本和沪深300基准，统计胜率、期望值、最大回撤与平均超额收益。
- **研究关联**：模拟交易自动关联同一公司的有效研究卡片；未关联研究逻辑的仓位会在驾驶舱和组合页提示。
- **本地数据迁移**：可在设置中导出/导入自选、研究卡片、策略记录和图表偏好，API Key 不进入备份。

### 2.4 可视化分时交互
- **专业级图表**：集成 Lightweight Charts，支持秒级分时走势。
- **悬浮动态数据板**：鼠标悬浮分时线时，实时显示该点位的**具体价格、时间及相对于昨日收盘的动态涨跌幅**。

## 3. 技术架构设计

### 3.1 后端行情引擎 (`/backend`)
- **核心框架**：Python FastAPI (异步非阻塞架构)。
- **行情适配层**：
  - `fetch_tencent_data`: 批量获取实时行情与异动检测。
  - `fetch_indices`: 指数（上证、深成、创指）同步抓取。
  - `fetch_sectors`: 领涨行业板块抓取。
- **AI 交互层**：集成 `google-genai`，开启 `tools=[{"google_search": {}}]` 联网搜索增强，消除大模型幻觉。
- **双工通信**：WebSocket 维持长连接，支持前端动态订阅（`subscribe`）不同自选池。

### 3.2 前端交互界面 (`/frontend`)
- **核心框架**：React 19 + TypeScript + Vite 8。
- **状态管理**：原生 `useState` + `useRef` 优化高性能 WebSocket 消息处理。
- **样式方案**：Tailwind CSS 4.0，支持深度定制的暗黑皮肤。
- **关键组件**：
  - `Chart.tsx`: 封装 Lightweight Charts，处理分时数据渲染与 Tooltip 逻辑。
  - `App.tsx`: 全局行情编排、Dnd 排序及页面路由。
  - `ResearchCenter.tsx` / `PortfolioCenter.tsx`: 公司研究与组合风险业务组件。
  - `StrategyLab.tsx`: 前向验证、基准比较、样本稳定性提示和联网逻辑复核。
  - `services/api.ts`: HTTP/WebSocket 通讯入口；`types/domain.ts`: 统一领域模型。
  - `utils/strategyMetrics.ts`: 策略与基准指标的纯计算层。
- **加载策略**：图表与三个研究业务页面采用动态导入，避免首屏加载完整业务包。
- **板块映射保护**：后台重建必须同时满足股票覆盖数、板块请求成功率和相对完整度门槛；不完整候选不会覆盖现有缓存，健康缓存替换前保留 `.bak` 备份。健康状态通过 `/api/health` 和页面底栏展示。
- **长短期样本隔离**：板块详情默认使用最多200只、按流通市值覆盖的长期样本，不再从当日涨幅前40只中选股；短期模式单独使用涨幅样本和技术信号。长期候选按规模、当前PE/PB、营收/利润同比、换手与字段覆盖度形成研究排序，明确不等同于买入建议。

## 4. 开发、测试与维护指南

### 4.1 环境准备
- **后端**：Python 3.12+，需安装 `requirements.txt` 中的依赖。
- **前端**：Node.js 18+，使用 `npm install` 安装依赖。

### 4.2 运行指令
- **一键启动**：根目录下执行 `sh start_all.sh`。
- **手动调试**：
  - 后端：`cd backend && source venv/bin/activate && python main.py`
  - 前端：`cd frontend && npm run dev`

### 4.3 自动化测试
- **后端回归测试**：执行 `cd backend && venv/bin/python -m unittest -v test_market_parser.py`，覆盖行情解析、数据日期、WebSocket 容错、AI模型顺序、资讯情绪兜底和复盘边界。
- **WebSocket 连通性测试**：执行 `backend/venv/bin/python backend/test_ws_v2.py`。
- **前端检查**：执行 `cd frontend && npm run build && npm run lint`。

### 4.4 后续维护建议
1. **行情接口扩展**：若腾讯接口频率受限，可在 `main.py` 的 `fetch_tencent_data` 中加入对新浪或东财 API 的容灾切换逻辑。
2. **AI 模型顺序**：AI 功能依次调用 `antigravity-preview-05-2026`、`gemini-3.5-flash`、`gemini-3.1-flash-lite`、`gemini-2.5-flash`，前一项不可用时自动降级。
3. **性能优化**：当自选股超过 100 只时，建议在前端引入虚拟列表（Virtual List）渲染。
